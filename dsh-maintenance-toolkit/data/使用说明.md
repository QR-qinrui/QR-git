# DeepSeek Harness 一键启动程序（最终单文件版）
> 公开发布版已脱敏：本机绝对路径已替换为 <launcher-root>（一键启动器目录）与 <user-home>（用户主目录）占位符。

**目录里只有一个启动脚本**：`一键启动DeepSeek-Harness.bat`（自包含）。

双击它 = 智能启动；传参数 = 各种功能模式。旧的 6 个启动器脚本与散落的
验证/探针脚本（build-and-test、verify、route-smoke、scan-logs、
verify-client、import-check、check-requires、cdp 探针等）的功能**全部内嵌
在这一个文件里**，其余脚本已归档到 `launcher-backup\archive-*`。

> 能力总览：**内置**（依赖/插件/工具全内嵌，无外部硬编码依赖）·
> **自检测**（-Doctor 全量诊断 + 启动时自动健康检查）·
> **实时更新修正优化**（-CheckUpdate 版本检测 + -Maintain 深度维护 + 智能启动自纠错）

## 工作原理

- bat 壳（前 12 行）每次运行把内嵌的 PowerShell 引擎解出到
  `%LOCALAPPDATA%\DeepSeek-Harness\engine.ps1`（每次刷新，永远完整）。
- 引擎按需把 6 个内嵌 Node 工具（CDP 在线验证、路由冒烟、日志扫描、
  import 形状检查、open-in-tui 客户端契约验证、无头浏览器 CDP 库）解出到
  `%LOCALAPPDATA%\DeepSeek-Harness\tools\`，内容哈希校验，损坏自动重写。
- 全部路径自适配：Node / npm / dsh / chat-manager / open-in-tui / Chrome/Edge /
  服务端口 / 认证 URL 都是自动探测，没有硬编码依赖。

混传参数（自动识别并摘除，其余原样转发给 dsh web）：

## 自检测 + 自纠错清单

1. 服务已在线且健康 → 幂等跳过，直接打开页面
2. 端口被残留 node 进程占用但无响应 → 自动清理重启
3. 端口被非 node 进程占用 → 拒绝误杀，明确提示
4. chat-manager 源码比 lib 新 / 语法损坏 / 含非种子词 require → 自动重建
5. 首次启动超时 → 清理残留自动重试一次
6. 测试 profile 缺基础组件 → 自动从 web 配置引导（共享插件集）
7. 工具文件损坏 → 哈希校验自动重写
8. 无头浏览器验证残留进程/临时目录 → 自动清理（5 分钟保护窗口）
9. 启动器被篡改 → 提示 -Verify / -Restore
10. 找不到 dsh → 自动改走 npx 在线方式启动
11. **版本过期 → -Doctor/-CheckUpdate 提示，-Maintain 深度维护（新增）**

## 宿主版本与插件兼容性备注（2026-09-30）

**更正（同日复核）：DSH 宿主有运行时兼容门禁，而且 0.1.7-rc.2 就已经有了。**

- 门禁在 `@deepseek-ai/dsh-app-boot` 的 `evaluatePluginCompatibility`：读插件
  `peerDependencies` 里所有 `@deepseek-ai/dsh*` 条目，用 `semver.satisfies` 与宿主版本比对，
  不匹配就把该 bundle 记为 incompatible，并在启动时**跳过**
  （`dsh: skipping profile bundle "..."`）。它**不看** `peerDependenciesMeta.optional`，
  也**不看** `dsh.engines` 字段。
- 所以有两道彼此独立的门：**市场门**（安装前读 registry 的 `dsh.engines.dsh`，不匹配就拒绝装）
  与**宿主门**（每次启动按 `peerDependencies` 决定挂不挂）。
- 实测（`dsh --dump-config`，宿主 0.1.7-rc.2）：`@linxin666/dsh-web-all@0.4.4`（peer `>=0.2.0-rc.1`）
  与 `dsh-better-sidebar@0.24.1`（peer `^0.2.0-rc.1`）**已被跳过**，
  `cordis.patch.yml` 里 8 条 `patch: entry "web-ui-*" not found` 就是连带症状。
  ⚠️ 界面上一时还能用，是因为运行中的会话是在它们兼容时启动的（代码已在内存里），
  **下一次重启就会掉**。
- 结论修正：`0.4.4` 装上去"暂时可用"不等于兼容；要长期稳定必须让**宿主门**也通过
  （宿主升到 ≥0.2.0-rc.1，或给该精确版本开豁免）。
- **注意：`runtime\` 里还有本机私有 UI 补丁**（`patch-runtime-tree.mjs` 改写的
  `@deepseek-ai/dsh-client-ui-*`：挽具框架 CSS、暗色默认、服务状态点、skip-link、移动端适配等）。
  升级宿主会连这些一起换掉，所以升级流程带 **P2.5 补丁门禁**：先用
  `tools\check-runtime-patches.mjs` 检查，干净态用 `tools\apply-runtime-patches.mjs` 事务化打上
  （全部锚点命中才写回）。已实测：同一套 23 条锚点在 0.2.0-rc.2 上 **23/23 可原样应用**，
  打完后的签名与旧运行时逐小节一致，界面（暗色 `#0a0e14` + 服务状态点 + skip-link + 家族包）完整复现。
- **自动化升级**：双击 `开始自动升级.cmd` → 按任意键 → 关掉启动器窗口，剩下全自动完成
  （等待 → 升级 → 断言 → 失败自动回滚 → 重启），日志在 `logs\自动升级-*.log`。
  想先看计划用 `开始自动升级.cmd -DryRun`，或跑 `升级DSH运行时.ps1 -Analyze`。
- 升级流程可用 `-Root <沙箱目录>` 做**完整破坏性演练**（junction 镜像生产目录，含交换与回滚），
  不碰正在运行的 runtime 与 profile；本次演练就是这样一次跑通并抓出 5 处问题的。

**npm dist-tags 现状（2026-09-30 实测）**：`latest = 0.2.0-rc.2`、`next = 0.2.0-rc.2`、
`alpha = 0.1.7-alpha.2`。即「升到 ≥ 0.2.0-rc.1」现在走 `@latest` 即可，不需要指定 next 频道。

**坑：`-CheckUpdate` / `-UpgradeDsh` 升不到本体。**

- 启动器实际运行的宿主是内置运行时 `runtime\node_modules\@deepseek-ai\dsh`
  （`Get-DshCmd` 里 `runtime\dsh.cmd` 优先级高于 PATH 与 npm 全局）。
- `-UpgradeDsh` 执行的是 `runtime\node.exe` + 内置 npm 的
  `install -g @deepseek-ai/dsh@latest`，而内置 npm 的全局 prefix 实测是
  `<user-home>\AppData\Roaming\npm`（不是 `runtime\`）。装完**启动器仍然优先
  `runtime\dsh.cmd`** → 界面会打印「更新完成」，但宿主版本不变，市场看到的还是旧版本。
- 真要升本体：就地升内置运行时（**先停服务**，否则原生模块被占用会失败）：

  ```powershell
  runtime\node.exe runtime\node_modules\npm\bin\npm-cli.js install --prefix runtime @deepseek-ai/dsh@latest
  ```

  `runtime\dsh.cmd` 用相对路径指向包内 `bin.js`，升级后自动生效，重启即用。

**升到 0.2.0-rc.2 时会被宿主门跳过的 4 个插件及处置（2026-09-30 实测）**：
`dsh-session-insights`（升 0.5.1；它的 peer **精确 pin** `0.2.0-rc.1`，与 latest 的 rc.2 差一个 patch 级预发布，故附一条精确豁免）、`deepseek-idesign`（本地 link 包，
4 条 peer 放宽为 `<0.3.0-0` 即原生通过，原包备份在同目录 `package.json.bak-*`）、
`dsh-context-doctor@0.7.2` 与 `@loserfox/distill@0.1.0`（上游仍为 0.1.x，升无可升，
已开 0.2.0-rc.2 精确豁免；`dsh-session-insights@0.5.1` 同样需要一条精确豁免；全部记录在 profile 的 `compatibility.json`）。
另外 0.2.0 把 `time-context` / `schedule` / `ui-schedule` 移出了默认 Web 组合，
需在 profile 的 `dsh.profile.bundles` 补 `@deepseek-ai/dsh-experimental-schedule-bundle`。

### v2.3.1 热修（2026-09-29，提权重入崩溃修复）

**问题**：服务需要提权启动/修复时，提权窗口瞬间报错 `GetFullPath：路径中具有非法字符` 并退出。

**根因**：启动器目录以反斜杠结尾（`D:\...\程序\`），提权重入构造命令行时该值被包成 `"...\程序\"`；按 Windows `CommandLineToArgvW` 规则，结尾的 `\"` 会被解析为转义引号，提权进程实际收到的值末尾混入一个字面引号，`GetFullPath` 因此抛错。

**修复**（双层）：
1. 命令行构造：被引号包裹且以 `\` 结尾的参数，结尾反斜杠加倍（`"...\程序\\"`），子进程解析后还原为原值——覆盖 `-DshLauncherDir` 及所有转发参数（如用户传入的 `-NodeDir "C:\xxx\"` 同类场景）。
2. 接收端防御：`-DshLauncherDir` 在 `GetFullPath` 前先剥离可能混入的字面引号与空白。

**验证**：系统 API 级往返实测 3 组场景全部一致；真实提权实例日志确认收到正确目录、通过引擎初始化与基线自检（修复前在启动第一行即崩溃）。

## v2.4 内置运行时（2026-09-29，纯本地化整合）

**功能**：dsh Web 服务所需的全部运行资源随启动器打包于 `runtime\` 目录（node.exe v26 + @deepseek-ai/dsh 0.1.7-rc.2 + npm，共约 1135MB），启动器内置模块开箱即用。

| 要求 | 实现 |
| --- | --- |
| 无需额外安装或配置 | 探测链优先级：`-NodeDir` 显式指定 > **内置 runtime** > PATH > 系统候选路径。把整个启动器目录拷到一台没有装过 Node/dsh 的 Windows 机器上，双击即可启动 |
| 断网/服务不可用不影响 | 内置 dsh 直启不经过 npx/网络；版本检查等云端请求均为「可跳过」的显式模式，网络受限时自动降级跳过（-Doctor 实测：网络受限 → 跳过版本检查，其余全绿） |
| 避免运行时云端请求 | 启动链路零云端请求；仅 -CheckUpdate/-UpgradeDsh/-Maintain 三个用户显式触发的模式会访问上游（只读或经确认的更新操作） |
| 启动速度 | 健康路径 1.8 秒免提权直达；内置运行时免去 npx 首次下载（此前无 dsh 环境首次启动需下载数百 MB） |

**界面标注**：-Doctor 与启动流程中，来自内置运行时的 node/dsh 会标注「内置运行时·离线可用」，一眼可辨。

**边界说明**：dsh 的 AI 对话能力本身需要调用用户自行配置的模型服务（这是产品功能，非启动器行为）；启动器及内置运行时不向任何云端接口发起运行时请求。

**性能瓶颈说明与优化**：
1. 冷启动耗时主要在 node 进程初始化与 dsh 模块加载（数千个小模块文件的 I/O）。已通过「健康实例复用」（服务在线时 1.8 秒直达、不重启）规避重复冷启动。
2. runtime 目录含约 1.1GB 数万个小文件，杀毒软件实时扫描会拖慢首次/冷启动的模块加载。如感知冷启动偏慢，可将启动器目录加入杀毒软件排除列表（需在 Windows 安全中心手动操作，属系统安全设置，启动器不做静默修改）。
3. 磁盘占用为一次性静态成本，node 按需加载模块，不会全量读入内存，对运行期性能无影响。

## v2.5 纯本地一键启动（2026-09-29，双击免 UAC 直达网页版）

**解决的问题**：双击启动器无法自动启动并打开 DeepSeek Harness 网页版，必须依赖外部程序（如 WorkBuddy）把服务拉起来。

**根因（三层，逐层实测复现并修复）**

1. **含空格路径参数被截断（长期根因）**：启动目录 `<launcher-root>\...` 恒含空格，而 PowerShell 5.1 的 `Start-Process -ArgumentList` 数组拼命令行时不给含空格元素加引号——dsh 程序入口路径在首个空格处被截断（服务日志实锤 `Cannot find module '<launcher-root>\deepseek'`），node 直接退出，服务永远起不来。
2. **环境变量大小写并存崩溃**：部分宿主向子进程环境注入第二份变量（`Path`+`PATH`、`http_proxy`+`HTTP_PROXY`），`Start-Process` 构造子进程环境字典时因重复键直接抛「Item has already been added」，启动器异常退出。
3. **冷启动强制提权**：v2.2 的延迟提权设计在需要启动服务时弹 UAC——而启动 dsh（监听用户端口）、自愈（写用户目录）、清理残留 node（同用户进程）根本不需要管理员权限；UAC 环节一旦取消/异常即失败。

**修复内容**

| # | 修复 | 实现 |
| --- | --- | --- |
| 1 | 参数补引号 | Start-DshManaged 三个启动分支（bin.js / npx / ps1）对含空格参数显式内嵌引号 |
| 2 | 环境通用去重 | 引擎初始化时扫描全部大小写并存的同名变量：PATH 拼接去重、其余取首个非空，消除重复键 |
| 3 | 冷启动免提权 | Auto/Foreground/Stop/Restart/Rebuild 全部免 UAC；仅 -Restore/-UpdateBaseline（写只读基线文件）保留前置提权 |
| 4 | 启动器自主打开网页 | 新增 Open-DshWeb：服务就绪后从服务日志提取**带认证 token 的 URL** 直通打开（node stdout 块缓冲，短重试最多 3 轮）；找不到 token 退回裸地址。dsh 托管启动统一 `--no-open`，杜绝双开标签 |
| 5 | 计划任务注册适配 | OpenViking 持久看护的 Register-ScheduledTask 需管理员——普通用户身份跳过并如实提示（原实现失败时仍打印"已注册"误导信息） |

**实测证据（普通用户、零 UAC、含空格路径、含重复环境变量的完整冷启动）**：23.1 秒服务就绪（HTTP 401）→ `打开页面：http://127.0.0.1:3080/?token=Zx_J2K...`（带认证直达）→ 服务常驻。停止服务 = 关闭启动器窗口。

**使用方式**：双击 `一键启动DeepSeek-Harness.bat` 即可。服务在线时约 2 秒直达；掉线时自动拉起（约 25 秒）并自动打开网页。**不再需要任何外部程序托管服务。**
