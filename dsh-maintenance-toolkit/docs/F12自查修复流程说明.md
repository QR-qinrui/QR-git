# F12 自查修复流程 · 总结与可复现说明

## 一、流程总结（5 个阶段）

| 阶段 | 做什么 | 为什么 |
| --- | --- | --- |
| 1. 服务探活 | dsh web(:3080) / Ollama(:11434) / OpenViking(:1933) | 先确认「病人在不在」，服务未起时后续检查无意义 |
| 2. 补丁完整性 | 检查 5 个幂等补丁标记（pet-host / pet-client / prompt-enhance / ego-host / whale-widget），缺失时自动重跑 apply-adaptations.ps1 | 历史错误 90% 是插件升级覆盖补丁导致；这是更新兼容的核心 |
| 3. 宿主路由冒烟 | 用启动日志里的 token URL 探测关键 API | 快速验证 pet 200、ego watch/stop 语义、changes.summary 设计 404 |
| 4. 真实浏览器 F12 采集 | 无头 Chrome + CDP 抓取 15 秒：console.error / 异常 / 网络 4xx/5xx / boot 状态 | 复现用户 F12 所见，而不是猜 |
| 5. 分类与报告 | 按签名表分类，写时间戳报告，给出 PASS / REVIEW | 把经验固化成可判断的规则 |

## 二、流程特点

1. **实证优先**：一切结论来自真实浏览器 CDP 采集 + 真实 API 探测，不用猜。
2. **更新兼容**：补丁不是一次性手工改，而是 `patch-data.json + apply-adaptations.ps1` 幂等重放；升级流程自动调用，本脚本再兜底核验。
3. **签名分类**：错误被映射到已知签名（pet-404 / ego-409 / agent-team-react130 / changes-summary-404 / ollama-500 / whale-audio），设计行为与真故障分开。
4. **可降级**：浏览器不可用、无 token、无 Chrome 时逐级降级，其余阶段照常执行，不因单点失败而中断。
5. **可审计**：每次运行落一份 `f12-report-<时间戳>.md`，留痕可回溯。

## 三、可复现用法

```bat
:: 双击
f12-audit-repair.cmd

:: 或 PowerShell
powershell -ExecutionPolicy Bypass -File f12-audit-repair.ps1            :: 全量（含无头浏览器采集）
powershell -ExecutionPolicy Bypass -File f12-audit-repair.ps1 -SkipCapture :: 跳过浏览器采集（快速体检）
powershell -ExecutionPolicy Bypass -File f12-audit-repair.ps1 -NoRepair    :: 只查不修
powershell -ExecutionPolicy Bypass -File f12-audit-repair.ps1 -LiveUrl <url> :: 手动指定 token URL
```

退出码：0 = PASS，1 = REVIEW。报告输出在脚本同目录。

## 四、核心稳效保障

- **幂等**：脚本可反复运行；补丁检查与 apply-adaptations.ps1 均为幂等。
- **自愈**：补丁缺失 → 自动重跑 apply-adaptations.ps1；Ollama models 悬空 junction → 自动改名并还原 models.bak-*（无权限时明确提示提权重试）。
- **健壮**：全部网络探测走 .NET HttpClient（避免 Invoke-WebRequest 控制台缓冲 bug）；node 直调不走 cmd 包装；工具目录不可写时自动落到 `.f12-tools`。
- **嵌入式采集器**：`f12-capture.mjs` 随脚本自包含，不依赖 agent 工具链，普通 PowerShell 即可跑。

## 五、错误签名表（如何扩展）

分类函数 `Classify-Entry` 内按「URL 关键字 + 状态码 / 文本模式」匹配：

| 签名 | 判定 | 处置 |
| --- | --- | --- |
| pet-404 | url 含 /api/pet/ 且 404 | 补丁缺失 → Phase 2 已自动重打 |
| ego-watch-stop-409 | url 含 /api/ego/watch/stop 且 409 | 补丁缺失 → Phase 2 已自动重打 |
| agent-team-react130 | 文本含 React error #130 / slot entry crashed | 第三方 agent-team 旧 API；已卸载，重装需先适配 |
| changes-summary-404 | url 含 /api/changes.summary 且 404 | 设计行为，忽略 |
| ollama-tags-500 | url 含 11434/api/tags 且 500 | models 悬空 junction → Phase 1 自动修复 |
| whale-audio-warning | 文本含 AudioContext | 手势门控补丁缺失 → Phase 2 重打 |
| net-abort | 文本含 ERR_ABORTED | 导航中止噪音，忽略 |

新增问题 = 在 `Classify-Entry` 加一行签名 + 在对应 Phase 加一个探测/修复动作。

## 六、自动化升级闭环（upgrade-plugins.ps1）

把「升级 → 补丁 → 重启 → 验收」串成一条命令：

```bat
upgrade-plugins.cmd            :: 只检查版本 + 跑验收（安全，不改任何东西）
upgrade-plugins.cmd -Apply     :: 有新版则：备份 → pnpm 升级 → 重打补丁 → 重启服务 → F12 验收
```

升级目标（watched）：`@linxin666/dsh-web-all` / `dsh-whale-widget` / `dsh-prompt-enhance` / `dsh-context` / `dshmarket`。

关键设计：
- **先备份**：package.json / pnpm-lock / pnpm-workspace / cordis.patch.yml / patch-data.json / installed-versions-before 全部落到 `_归档\backup\upgrade-auto-<时间戳>`，可回滚。
- **精确升级**：`pnpm add <pkg>@latest --save-exact`，只动有新版的目标包。
- **验收即门槛**：升级后自动重跑 apply-adaptations.ps1（补丁 + engine-floor 归一化 + 链接修复），再跑 f12-audit-repair.ps1；两者任一不过 → 退出码 1 并留报告。
- **版本比较已归一化**：`^0.60.0` 与 `0.60.0` 视为同版，避免误报。

## 七、兼容优化（已完成）

1. **engine-floor 归一化改为正则通用匹配**（apply-adaptations.ps1 Patch 4）：任何 `"dsh": ">=X"` / `"@deepseek-ai/dsh": ">=X"` 声明都归一化到 `>=0.1.7-rc.2`，不再依赖 `>=0.2.0-rc.1` 字面量。实测本轮多覆盖 4 个 0.4.4 家族包。
2. **F12 报告新增 watched 插件版本**：报错与「升级到哪个版本」直接关联。
3. **签名表可扩展**：新错误 = `Classify-Entry` 加一行 + 对应 Phase 加探测/修复动作。
