# 插件无损升级流程（可复现工作流）

> 沉淀自 2026-09-30 两次实战：dsh-web-all 全家桶 0.4.3→0.4.4（19 包）+ 全 profile 插件升级（8 包）。
> 核心产物：`update-plugins.ps1`（检测/预检/备份/升级/补丁/验证一键工作流）、`apply-adaptations.ps1`（本地补丁 + Patch 4 引擎下限归一化）。

## 一、流程总结（八阶段）

| 阶段 | 做什么 | 关键要点 |
|---|---|---|
| 1 检测 | 以 npmjs 为基准对比已装版本，github 依赖比对锁文件 commit | 不轻信任何镜像；`file:`/`link:` 本地件与 @deepseek-ai/* 宿主包跳过 |
| 2 镜像同步 | 升级目标版本必须在 npmmirror 已同步 | 镜像滞后会让 pnpm `downloaded 0` 静默不升级——本次实战踩过 |
| 3 兼容预检 | 三层：①@deepseek-ai/* peer 硬门槛（0.1.x/0.2.x 宿主线）；②dsh.engines 软门槛（可归一化）；③`-Deep` 补丁锚点顺序模拟 | 硬不兼容→自动选"宿主兼容线最新版"（better-sidebar 0.24.1→0.22.1）；无兼容版→暂缓（session-insights 0.5.1） |
| 4 备份 | package.json / pnpm-lock / pnpm-workspace / patch-data / 脚本 → `插件自愈中心\备份\upgrade-auto-<时间戳>` | 任何失败都可恢复 |
| 5 安装 | 改 package.json 版本号（保留 ^/~ 风格）→ `pnpm install --ignore-scripts --config.minimumReleaseAge=0`；github 依赖 `pnpm update` 重解析 | 插件均为纯 JS，忽略脚本安全；cpu-features 无编译器构建失败因此绕开 |
| 6 补丁重打 | 调 `apply-adaptations.ps1`（幂等：pet / prompt-enhance / ego / whale / junction / Patch 4 引擎下限） | 升级必然覆盖 node_modules，补丁必须每次重打 |
| 7 验证 | 版本核对 + 回环 API 探针（degraded/rows/pet/whale/update-status）+ cloudflared.exe 恢复检查 | 明确指标：0 控制台错误、API 全 200、degraded 空、插件列表"异常"=0 |
| 8 记录 | 自动写 `修复记录-<时间戳>-自动升级.md`（清单/暂缓/验证/回滚步骤） | 加 dsh-memento 记忆与备份归档 |

## 二、核心特点（为什么这样设计）

1. **双源确认**：npmjs 是地面真值，npmmirror 是实际下载源——两个都查，缺一不动手。
2. **三层兼容预检**：peer 硬门槛（拦真正不兼容）、engines 软门槛（归一化元数据即可）、补丁锚点模拟（本地改动冲突提前暴露），把"升完再修"变成"升前就知道"。
3. **无损原则**：先备份 → 幂等补丁 → 失败即停并给出回滚命令；配置文件（cordis.patch.yml、版本快照）永不改动。
4. **最优兼容版本选择**：大版本不兼容时自动降档到"宿主兼容线最新版"，而不是粗暴跳过或硬升。
5. **纯 JS 安装通道**：`--ignore-scripts` 规避本机无 C++ 编译器的原生构建失败；真正需要的二进制（cloudflared.exe）单独用 curl 恢复并校验 MZ 头。
6. **验证指标化**：错误数、HTTP 状态、台账内容、异常标签计数全部量化，不靠"看起来正常"。
7. **沉淀闭环**：报告 + 记忆 + 备份三件套，下次升级有据可查、可回滚、可审计。

## 三、脚本用法

```powershell
# 检测模式（默认，只读不落盘）
powershell -ExecutionPolicy Bypass -File update-plugins.ps1

# 自检：semver 断言 + 补丁标记 + 全量锚点模拟（下载当前版本 tarball）+ 引擎下限 + API 探针
powershell -ExecutionPolicy Bypass -File update-plugins.ps1 -SelfTest

# 深度检测：对"待升级且带本地补丁"的包做新版本锚点预检（慢）
powershell -ExecutionPolicy Bypass -File update-plugins.ps1 -Deep

# 执行升级（检测通过的计划）
powershell -ExecutionPolicy Bypass -File update-plugins.ps1 -Apply

# 自动化模式：只升 npm 插件（跳过 ego-browser 等 git 依赖，避免无人值守时重启浏览器窗口）
powershell -ExecutionPolicy Bypass -File update-plugins.ps1 -AutoApply

# 只检测指定插件（支持通配）/ 宿主版本重新标定
powershell -ExecutionPolicy Bypass -File update-plugins.ps1 -Filter "dsh-*"
powershell -ExecutionPolicy Bypass -File update-plugins.ps1 -HostVersion 0.2.0-rc.1
```

## 三·五、自动化升级（已部署）

- `auto-update.ps1`：调 `update-plugins.ps1 -AutoApply`，全量日志写 `插件自愈中心\logs\auto-update-<时间戳>.log`，一行结论追加 `auto-update-history.log`（审计）。
- Windows 计划任务 **DSH-Plugin-Lossless-AutoUpdate**：每天 02:30 自动执行（登录时运行）。查询：`schtasks /Query /TN "DSH-Plugin-Lossless-AutoUpdate"`；删除：`schtasks /Delete /TN "DSH-Plugin-Lossless-AutoUpdate" /F`。
- 自动化安全边界：只升级 npm 插件；git 依赖（ego-browser 等）留给人工 `-Apply`（会重启浏览器窗口）；宿主门禁插件（0.2.0 线）自动跳过并在 `-Apply` 时把 caret 规格 pin 成精确版本，防止日后误拉不兼容版。

回滚：备份目录里恢复 package.json / pnpm-lock.yaml / pnpm-workspace.yaml 后执行
`pnpm install --config.minimumReleaseAge=0 --ignore-scripts` + 重跑 `apply-adaptations.ps1`。

## 四、完善点（在实战基础上的增强）

1. **自动版本决策**：不再手工查 peer，脚本自动找"宿主兼容线最新版"并写进计划。
2. **镜像同步门禁**：升级前自动确认 npmmirror 已同步目标版本；-Apply 时未同步会等待（最多 10 分钟/包），杜绝静默失败。
3. **补丁锚点预检**：`-Deep` 升级前模拟；`-SelfTest` 随时对当前版本全量模拟（4 个补丁目标 + whale 标记 + 引擎下限 + 5 路 API 探针）。
4. **引擎下限自动归一化**：Patch 4 把 0.4.4 家族 `>=0.2.0-rc.1` 声明归一到宿主线，插件管理器"异常"标签自动清零，重装后自动重打。
5. **git 依赖精准比对 + 磁盘缓存**：github: 依赖按锁文件 commit 与仓库 HEAD 比对；GitHub API 结果缓存 30 分钟（扁平 JSON 数组格式），限流时用旧缓存兜底，不再误报。
6. **宿主门禁 pin**：宿主不兼容的 caret 规格自动改精确版本，防止未来误升级。
7. **PS 5.1 三坑免疫**（实测踩坑后固化）：
   - 脚本文件必须 **UTF-8 with BOM**，否则 PS 5.1 按 GBK 误读中文路径字面量，会静默读写到乱码目录（`插件自愈中心` → `鎻掍欢鑷剤涓績`）；
   - 跨函数只传标量/字符串：PS 5.1 中函数内调用函数时对象返回值会被字符串化（`return [pscustomobject]@{...}`、嵌套对象 JSON 往返都中招）；
   - `Invoke-WebRequest` 对 4xx 抛异常而非返回状态码：401（浏览器信任栅栏）在 catch 里按"路由已注册"判通过。
8. **SelfTest 退出码**：0=全绿，1=存在失败项——可直接挂进 CI/巡检。

## 五、已知边界与注意事项

- **宿主 0.1.7-rc.2 暂缓名单**：dsh-session-insights 0.5.1、dsh-better-sidebar 0.24.1（peer 锁死 0.2.0-rc.1）。宿主升级到 0.2.0-rc.1 后用 `-HostVersion 0.2.0-rc.1` 重新检测即可解锁。
- **ego-browser 升级会热重载插件并重启 ego worker / agent 浏览器窗口**，升级时避免正在进行的浏览器任务。
- **pnpm 12 的 allowBuilds 白名单**：cpu-features/node-pty/ssh2 无编译器构建会失败，本流程用 `--ignore-scripts` 绕开；这些包无构建产物时按纯 JS 回退运行（ssh2 可选依赖，实测无影响）。
- **cloudflared.exe** 由 postinstall 下载，不在 npm tarball 里；`-Apply` 会自动检测并恢复。
- 与维护体系衔接：`maintain.ps1 -Fix` 会重跑 `apply-adaptations.ps1`；建议每周或每收到"有新版本"提示时跑一次 `update-plugins.ps1` 检测。
